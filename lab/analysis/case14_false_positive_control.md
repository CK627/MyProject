# case14：真实流量三处误报治理（TLS 伪文件 / 假 JPEG / HTML 假命令）

**类型**：误报治理（真实恶意流量样本上的降噪）
**样本**：批量恶意流量分析题（28 份抓包）扫描后暴露的三类系统性误报

## 误报 1：TLS 加密流里"雕刻"出文件

**现象**：从 443 端口 TLS 流中提取出多个 0.1–8 MB 的 `.jpg`（有的编号还连号）。
**根因**：TLS 应用数据是密文，高熵字节里偶然出现 `FF D8 FF … FF D9` 序列——
签名匹配纯属巧合。**密文里不存在真实文件**。
**判别**：看第 4 个字节（见下）；再看提取来源是不是 443/TLS 流。
**修复**：方向流以 TLS 记录开头（`0x16/0x17 + 03 0x`）或前 256KB 含合理握手记录
→ **整个流跳过文件雕刻**（明文 HTTP over 443 不受影响），输出「跳过 N 个 TLS 加密流」。
实测：单题最多跳过 800+ 个流，伪文件清零，真实提取（HTTP 流）不受影响。

## 误报 2：假 JPEG（FFD8FF 巧合）

**现象**：非 TLS 流中也偶现"JPEG"，打开是花屏/损坏。
**判别（记牢）**：`FF D8 FF` 之后的**第 4 个字节必须是合法 JPEG 段标记**：
`E0–E5`（APP0–5）/ `DB`（DQT）/ `C0–C3`（SOF）/ `ED`（APP13）/ `EE`（APP14）/ `FE`（COM）。
**修复**：雕刻 JPEG 时校验第 4 字节，不在集合内直接丢弃。

## 误报 3：HTML 网页被读成"Windows 命令会话"

**现象**：一份 HTTP 文件服务器流量被识别出 6 个"Windows 交互会话"，
"命令"内容是整页 HTML：`</td></tr>`、`<a href="/C:">`、`2021-company-sched-template.xlsx</a>`——
且以 0.90 高置信度进入候选（会污染报告与训练数据）。
**根因**：①提示符正则把 HTML 里 `C:\...>` 字样当命令行提示符；
②"命令净化"只查 ASCII 占比，`</td></tr>` 全 ASCII → 通过。
**修复（双保险）**：
- 提示符正则：**行首锚定** `(?:^|[\r\n])` + 内容**禁 `<` `>`**；
- 命令净化：含 `<` / `&lt;` / `&gt;` 直接剔除（Linux 检测同理）。
**回归**：真 Windows 反弹会话（banner + 提示符 + 命令序列）照常识别；HTML 页 0 误报。

## 附带：主机表"网关折叠"（同类降噪）

ARP/Ethernet 主机表里全部远端 IP 都挂在网关 MAC 下 → 一个 MAC 挂 ≥5 个 IP
判定为路由器/网关，折叠一行，避免主机表被远端 IP 淹没。

## 第三轮补充（2026-10-13）：DNS 模块重建 + CSS 颜色闸门

**用户实测反馈**：`upload.pcapng` / Emotet-IcedID 两题出现大量"高 0.90 长域名
（可能为 DNS 外带）"，内容却是 `form-data; name="upload_file"…ms17-010.cn`、
`xmlns:rdf="http://…"`、`.layui-icon-loading…` 之类——**理论上根本不可能从中拿到东西**。

**根因 1（DNS 模块）**：`dns.py` 的抓包分支从未解析 DNS！它用
`[ -~]{3,50}\.(com|net|org|cn|…)`（**空格也算**）在全球原始字节里捞"像域名的字符串"，
且同一批"长域名"结论被重复追加两遍（重复输出）。
→ **重建**：复用扫描器同一套解析链（load_packets + l4_parse + dns_qname），
只统计 **UDP:53 的真实查询报文**（QR=0）；长域名判定增加结构条件
（**最长标签 ≥ 25 字符**，排除 CDN/广告类"多短标签拼接"长域名）；各分类封顶输出。
实测：42/81 个文件里的该类噪音全部消失；`FLAG 消失之谜` 的真外带域名
（56 字符 base64 标签）**保持 0.90 命中**。

**根因 2（CSS 颜色片段）**：网页样式 `color:#f2f2f2}` 的 6 位十六进制颜色被
"片段(尾)"模式 `xxxx}` 捕获（9 个/题），还生成垃圾拼接建议
`flag{f2f2f2}e2e2e2…}`。
→ 尾片段前置字符排除表加入 `#`（CSS 颜色上下文）。

**根因 3（证书 DER 字节巧合，全局性）**：`{0y0w` 这个"片段"出现在几乎所有题里——
溯源发现它是 X.509 证书 DER 的 `04 7B 30 79 30 77`（长度字节 0x7B + SEQUENCE 头）的
ASCII 形态；Windows 频繁拉取微软证书（CRL/OCSP），所以每题必现。
另一类 `2a2g2m2s2x2}` 等字母数字交替串同属证书/签名二进制区巧合。
→ 流量模式新增**控制字节密度闸门**：片段 ±140 字节内 `\x00-\x08 / \x0E-\x1F / \x7F`
（不含 \t\n\r）≥4 个 → 判定为二进制区，剔除；裸 `{` 开片段最小长度 4→6。
实测：`capture4` 的已知误报 `flag{0y0w0g0q0y0}` 及全语料该类噪音全部清零。

**回归**：冒烟新增 `t9-dns.pcap`（真外带长查询必须命中 / 良性长域名 + HTML·CSS·文件名
一律不得误报）；片段/拼接既有断言（evtx 严格模式）全部保持通过。

## 验收标准（回归夹具）

- `t7-tls.pcap`：TLS 流内嵌"合法头"伪 JPEG **不得**被提取；明文流真 JPEG **必须**提取
  （头 FFD8FFE0 / 尾 FFD9 完整）；HTML 页不得报"交互会话"；真 Windows 会话必须识别。
- 全量真实样本回归：TLS 伪文件清零；FTP/后门/反弹 shell 检测全部保留。
