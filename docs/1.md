# 第一章：项目概述与设计目标

## 1.1 为什么要做这个项目？（选题背景）

在大学校园里，学生们每天都有着五花八门的互助需求。比如到了毕业季，学长学姐们有大量带不走的闲置教材和二手物品需要处理；平时上课或者遇到恶劣天气，找人代拿快递、代买外卖、甚至求助学习资料等小事更是家常便饭。另外，学校里各种社团活动、失物招领等信息，往往被淹没在各个微信群和QQ群里。

我们平时最常用的解决办法就是发朋友圈或者丢到大群里。但这种方式其实挺让人头疼的：一方面，群里消息刷得太快，真正需要帮忙的信息很容易被错过；另一方面，群里经常混进校外的推销人员，大家互相也不认识，万一遇到个拿了东西不给钱的，连个说理的地方都没有。如果去闲鱼这种大平台，对这种只是跑个腿或者买本二手书的小事来说，又要寄快递又要付邮费，实在是不划算。

所以，我就想能不能自己动手写一个专门针对我们学校师生的“智慧校园服务平台”。把发帖子、发悬赏任务、聊天、甚至担保交易和信誉评价全都整合在一起，让大家在校园里的互助变得更靠谱、更方便。这就是我做这个毕业设计的初衷。

## 1.2 平台想做成什么样？（平台定位）

简单来说，我给这个平台的定位是一个“自带担保和信誉机制的校园互助社区”。它的核心逻辑是从“发布需求”到“沟通接单”，再到“付钱结算”和“互相评价”，全都在这一个平台上搞定。我希望这个平台能突出两个特点：“互助共享”和“安全可信”。“互助共享”就是大家可以在校园墙上畅所欲言，有什么困难随时发悬赏任务找人帮忙；“安全可信”是我花心思最多的地方，为了防止有人乱发广告或者接了单不干活，我设计了一套信誉积分系统。不仅如此，我还加入了类似贴吧那种大家一起投票删垃圾评论的机制，让学生自己来管理自己的社区。

## 1.3 到底要实现哪些目标？

为了让这个平台不是个只存在于演示里的“花架子”，我给自己定了四个方向的设计目标。

### 1.3.1 界面得好用（易用性目标）

现在大家都被各种精美的互联网产品养刁了胃口，如果界面做得太丑或者操作太复杂，肯定没人愿意用。所以我在前端设计上尽量走现代简约风。考虑到大家平时都是在宿舍用电脑，在外面用手机，我还专门做了响应式布局，保证不管用什么设备打开排版都不会乱。像“发布任务”这种核心功能，我尽量让流程变短，填完信息点一下就能发出去。

### 1.3.2 资金和信息得安全（安全性目标）

既然涉及到找人帮忙和悬赏，安全绝对是第一位的。在代码层面，我用了 JWT Token 来做登录验证，密码存进数据库之前也用 bcrypt 做了加密处理，防止被脱库。在业务逻辑上，为了保护隐私，像快递取件码、宿舍具体门牌号这种敏感信息，我在代码里做了限制，只有别人真正接了你的单之后，系统才会把这些信息展示给接单人看。

### 1.3.3 流程得跑得通（功能完整性目标）

一个互助平台，光能发任务不行，还得能把整个流程闭环。所以我不仅做了发任务的功能，还自己手写了基于 WebSocket 的实时聊天，让发单人和接单人能直接在网页上发消息沟通。沟通好了，钱先冻结在虚拟钱包里，任务做完了系统自动打钱，最后双方还能互相打个分。这样一整套逻辑跑下来，才算是一个真正能用的平台。

### 1.3.4 以后得能升级（可扩展性目标）

虽然这只是个毕业设计，但我也考虑到以后万一还要加新功能怎么办。所以我一开始就采用了前后端分离的架构，前端和后端各司其职，通过 API 接口通信。后端的数据库操作也用了 ORM 框架，现在是用轻量级的 SQLite 测试，如果以后数据量大了，只要改一行配置就能无缝切换到 MySQL。这种设计为以后可能加入的“二手跳蚤市场”、“失物招领专区”留足了空间。
