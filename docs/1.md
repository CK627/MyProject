# 第一章 绪论

## 1.1 项目背景
现在很多学校活动、社团活动和校友活动都已经不再完全靠人工处理了，尤其是报名、统计和签到这些重复性比较强的工作，如果还是用纸质登记、微信群接龙或者 Excel 手工整理，前期也许还能应付，但人数一多，事情就会变得很乱。比如同一份信息可能会被重复记录，后期核对比较费时间，活动当天还可能出现签到排队、座位信息查不到等问题。

福建师范大学广东校友会一周年庆典活动本身就不是一个单一环节的活动，除了要统计参会人数，还要处理家属人数、才艺节目、付款截图、座位安排和现场签到这些内容。真正整理起来会发现，事情虽然不是特别难，但很杂，而且改动会比较频繁。也正因为这样，我觉得做一个针对这次活动使用的小型管理系统，比单纯写一个展示网页更有实际意义。

## 1.2 项目意义
本课题的意义主要不在于把技术写得多复杂，而在于把活动中原本分散的工作流程整理得更清楚。通过这个系统，用户可以直接在线报名，管理员也能在后台统一查看数据、审核信息和处理签到。这样既减少了人工来回整理表格的工作量，也让整个活动流程更清晰。对我自己来说，这个项目也不是单独练某一项技术，而是把前端页面、后端逻辑、数据库操作和实际业务需求结合起来做一次完整练习。

## 1.3 国内外现状
目前网上已经有不少活动管理平台，可以完成报名、通知发布、信息收集等工作，从功能上看已经比较成熟。但是这些平台大多是面向通用活动设计的，虽然功能很多，却不一定适合校友会这种有自己流程的活动。比如本项目里需要处理付款截图审核、座位安排、移动端签到这些内容，如果直接套用通用平台，有些环节并不能很好对应。

另外，一些平台需要付费，或者配置项比较多，对实际活动组织者来说未必方便。相比之下，自己开发一套功能够用、界面简单、能直接服务这次活动的系统，会更符合本课题的目标。因此，这个项目既有一定的使用价值，也有比较明确的实践意义。

## 1.4 本文主要工作
本文主要从需求分析、系统设计、功能实现和测试几个方面展开。前面先结合活动的实际流程，对系统需要完成的功能进行了梳理；然后根据这些需求设计系统结构和数据库；接着完成前端页面、后台接口和主要功能模块的开发；最后再通过测试检查系统是否能够满足报名、审核、签到和数据处理等基本要求。
