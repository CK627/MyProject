校园互助是本平台最具业务价值与创新性的核心模块。针对传统校园互助群或跳蚤市场中存在的“信息零散、缺乏保障、容易跑单”等痛点，本系统将互助任务、钱包悬赏冻结与信誉评价体系深度融合，构建了一个完整的可信交易闭环。

## 3.3 系统核心亮点机制与实现

本节单独提炼系统中在算法设计与工程实践方面具有创新性和亮点的核心功能，并结合关键代码段进行深入分析。

### 3.3.1 信誉分与“优先分”匹配算法

为了保证校园互助的安全与质量，系统摒弃了传统的“先到先得”接单模式，而是将信誉系统与任务大厅深度结合。系统综合用户的信誉分与好评率计算出一个“优先分”。当接单者申请任务时，系统会**根据优先分进行降序排序**，确保高信誉用户始终排在申请列表的最前面，从而让发单人优先看到优质服务提供者。

其核心计算公式为：`优先分 = (信誉分 + 好评率 * 100) / 2`。这一算法不仅量化了用户的历史行为，还从源头上过滤了潜在的劣质服务提供者，极大地提升了互助交易的成功率与满意度。

**优先分算法的核心实现** (`backend/app/api/tasks.py`)：

```python
@router.get("/{task_id}/applications", summary="获取申请列表")
async def get_applications(...):
    # ... 省略权限与基本查询逻辑 ...
    
    # 计算每个申请者的优先分并排序
    def get_priority_score(application):
        profile = db.query(UserProfile).filter(UserProfile.user_id == application.applicant_id).first()
        if not profile: return 80  # 无评价记录时赋予默认值
        
        credit_score = profile.credit_score or 60
        approval_rate = (profile.positive_reviews or 0) / profile.total_reviews if profile.total_reviews > 0 else 1.0
        
        # 优先分核心算法 = (信誉分 + 好评率 * 100) // 2
        return (credit_score + int(approval_rate * 100)) // 2
    
    # 按优先分降序排序，让优质用户排在最前面
    return sorted(applications, key=get_priority_score, reverse=True)
```

### 3.3.2 基于WebSocket的多端同步与即时通讯

为了支撑校园互助中的实时沟通，本项目没有依赖第三方 IM SDK，而是自研了一套基于 FastAPI 与原生 WebSocket 的高可用即时通讯系统。
在工程实现上，后端通过 `Dict[int, Set[WebSocket]]` 维护了一个高效的连接池。利用 Python 的 Set 数据结构天然去重的特性，系统完美支持了单用户在多个设备（如手机、平板、电脑）同时登录。当有新消息时，系统会向该用户所在 Set 中的所有活跃连接广播消息，实现了真正的**多端同步**。
在前端，系统通过 `visibilitychange` 事件监听设备的锁屏与解锁状态，结合定时 Ping 心跳机制，实现了断网与休眠唤醒后的无缝自动重连，保障了消息送达的可靠性。

**后端多端消息推送核心代码** (`backend/app/websocket/connection_manager.py`)：

```python
class ConnectionManager:
    def __init__(self):
        # 存储每个用户的WebSocket连接：{user_id: {websocket1, websocket2, ...}}
        # Set 结构天然支持单用户多设备登录，避免重复
        self.active_connections: Dict[int, Set[WebSocket]] = {}
    
    async def connect(self, websocket: WebSocket, user_id: int):
        await websocket.accept()
        if user_id not in self.active_connections:
            self.active_connections[user_id] = set()
        self.active_connections[user_id].add(websocket)
    
    async def send_personal_message(self, message: dict, user_id: int):
        """发送消息给指定用户的所有活动连接（实现多端同步推送）"""
        if user_id not in self.active_connections:
            return
        
        for websocket in self.active_connections[user_id]:
            try:
                await websocket.send_json(message)
            except Exception:
                # 忽略因网络波动断开的死连接，后续由 disconnect 方法统一清理
                pass
```

### 3.3.3 哈希文件去重与“秒传”分层存储机制

在即时聊天与社区互动中，用户经常会发送相同的文件或图片（如校内通知截图）。为极大节省服务器存储带宽与磁盘空间，系统实现了一套基于文件 Hash 的秒传与引用计数机制。
当用户上传文件时，后端首先计算该文件的 SHA-256 Hash 值。若数据库中已有相同 Hash 的文件记录，系统会直接返回已有文件的引用（跳过物理写入操作），从而实现“秒传”。此外，物理文件存储采用哈希值前缀（如 `04/b2/...`）进行目录分层，防止单目录下文件过多导致 Linux 文件系统索引性能急剧下降。
针对“秒传”文件的清理，系统通过 `reference_count`（引用计数）字段记录文件被不同消息引用的次数，配合后端 APScheduler 定时任务，在夜间低峰期自动扫描并彻底删除引用计数归零的废弃物理文件。

**文件去重与分层存储核心代码** (`backend/app/utils/file_manager.py`)：

```python
class FileManager:
    def _get_storage_path(self, file_hash: str) -> Path:
        """根据哈希值生成存储路径(2级哈希分层存储避免单目录文件过多)"""
        # 例如: 04/b2/04b2a696a3384...
        return self.base_path / file_hash[:2] / file_hash[2:4] / file_hash

    async def save_file(self, file_data: bytes, message_id: int, mime_type: str, db: Session) -> FileMetadata:
        file_hash = self._calculate_hash(file_data)
        
        # 1. 检查数据库是否已存在该物理文件的 Hash
        existing = db.query(FileMetadata).filter(FileMetadata.file_hash == file_hash).first()
        
        if existing:
            # 2. 文件已存在, 增加引用计数 (触发秒传逻辑，节省带宽和磁盘)
            existing.reference_count += 1
            db.add(FileReference(file_id=existing.id, message_id=message_id))
            db.commit()
            return existing
        
        # 3. 新文件, 正常保存到磁盘
        storage_path = self._get_storage_path(file_hash)
        storage_path.parent.mkdir(parents=True, exist_ok=True)
        with open(storage_path, 'wb') as f:
            f.write(file_data)
            
        # ... 初始化元数据（reference_count=1）并保存至数据库 ...
```
