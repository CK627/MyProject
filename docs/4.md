# 第四章 关键技术实现

本章将深入解析系统开发过程中攻克的关键技术难点，包括大文件的分片上传机制、教师端的智能审批逻辑以及前端的响应式实现。

## 4.1 大文件分片上传与断点续传

为了突破 PHP 服务器对单次上传文件大小的限制（通常为 `post_max_size` 限制），并保证在弱网环境下的传输稳定性，系统实现了基于 HTML5 File API 的分片上传算法。

### 4.1.1 核心原理

1.  **文件切片**：前端利用 `Blob.prototype.slice()` 方法，将大文件（如 500MB）按固定大小（如 2MB）切割成数百个二进制数据块（Chunk）。
2.  **并发传输**：通过 JavaScript 循环或并发队列，将这些数据块逐个发送给后端。
3.  **后端合并**：后端接收到所有切片后，利用文件流操作将其按顺序合并还原为原始文件。

### 4.1.2 前端实现代码

```javascript
// js/upload.js 核心逻辑摘要
async function uploadFileChunked(file) {
    const chunkSize = 2 * 1024 * 1024; // 2MB per chunk
    const totalChunks = Math.ceil(file.size / chunkSize);
    const uploadId = generateUUID(); // 生成唯一上传标识

    for (let i = 0; i < totalChunks; i++) {
        // 计算当前分片的起始位置
        const start = i * chunkSize;
        const end = Math.min(file.size, start + chunkSize);
        const chunk = file.slice(start, end);

        // 构建表单数据
        const formData = new FormData();
        formData.append('chunk', chunk);
        formData.append('chunk_index', i);
        formData.append('total_chunks', totalChunks);
        formData.append('upload_id', uploadId);

        // 发送请求（支持失败重试）
        await fetch('/api/upload_chunk.php', {
            method: 'POST',
            body: formData
        });

        // 更新进度条
        updateProgressBar((i + 1) / totalChunks * 100);
    }
}
```

### 4.1.3 后端合并逻辑 (`ChunkUploader.php`)

后端采用面向对象方式封装了 `ChunkUploader` 类，统一处理分片保存与合并逻辑。

```php
// api/ChunkUploader.php 核心逻辑摘要
public function handle() {
    // 1. 保存当前分片到临时目录 chunks/{upload_id}/
    $this->saveChunk();

    // 2. 检查是否所有分片都已上传
    if ($this->isAllChunksUploaded()) {
        // 3. 执行合并操作
        $finalPath = $this->mergeChunks();
        
        // 4. 触发回调（如更新数据库、重命名文件）
        if ($this->onMergeComplete) {
            call_user_func($this->onMergeComplete, $finalPath);
        }
        
        // 5. 清理临时文件
        $this->cleanup();
    }
}
```

## 4.2 教师端智能审批流程

为了提高教师的批阅效率，系统设计了“自动流转”的审批逻辑。

### 4.2.1 自动跳转逻辑

在传统的审批流程中，教师批改完一个学生后需要关闭弹窗，刷新列表，再寻找下一个学生，操作繁琐。本系统实现了以下优化逻辑：

1.  **队列构建**：当教师打开审核界面时，前端会将当前列表中的所有“待审批”学生 ID 存入一个队列。
2.  **状态同步**：当教师点击“通过”或“打回”后，利用 Fetch API 异步更新后端数据库状态。
3.  **自动游标**：操作完成后，系统自动从队列中取出下一个学生 ID，并立即加载其文件详情，实现无缝切换。

### 4.2.2 实时数据同步

为了解决多人协作（如多位老师同时审核一个班级）时的数据冲突问题，前端实现了轮询（Polling）机制。

```javascript
// js/teacher-review.js 轮询逻辑
setInterval(async () => {
    // 每隔5秒静默获取一次最新状态
    const stats = await fetchClassStats();
    // 更新页面上的状态图标（仅更新变化的DOM节点，避免页面闪烁）
    updateStatusIcons(stats);
}, 5000);
```

## 4.3 Glassmorphism UI 实现

系统界面的一大亮点是采用了毛玻璃风格，这主要通过 CSS3 的 `backdrop-filter` 属性实现。

**关键 CSS 代码：**

```css
/* 玻璃卡片样式 */
.glass-card {
    background: rgba(255, 255, 255, 0.25); /* 半透明白色背景 */
    backdrop-filter: blur(12px);           /* 核心：背景模糊 */
    -webkit-backdrop-filter: blur(12px);   /* 兼容 Safari */
    border: 1px solid rgba(255, 255, 255, 0.18); /* 微弱的白边框 */
    box-shadow: 0 8px 32px 0 rgba(31, 38, 135, 0.37); /* 柔和的投影 */
    border-radius: 16px;                   /* 圆角 */
}
```

这种设计不仅美观，还能让背景的动态壁纸隐约透出，增强了页面的层次感和沉浸感。

## 4.4 安全机制实现

### 4.4.1 PHP Session 强认证

系统不依赖前端 LocalStorage 存储敏感信息，而是使用 PHP 原生 Session 进行服务端认证。

-   **登录**：验证成功后，服务器生成 `session_id` 并通过 `HttpOnly` Cookie 下发给客户端。
-   **鉴权**：所有 API 接口在执行业务逻辑前，首先调用 `checkSession()` 函数。若 Session 失效，直接返回 401 状态码，前端拦截后自动跳转至登录页。

### 4.4.2 SQL 注入防御

系统中所有涉及数据库查询的操作，均强制使用 PDO 预处理语句（Prepared Statements），严禁直接拼接 SQL 字符串。

```php
// 正确的写法：使用参数绑定
$stmt = $pdo->prepare("SELECT * FROM Users WHERE username = ?");
$stmt->execute([$username]);
$user = $stmt->fetch();
```

这一措施从根本上杜绝了 SQL 注入漏洞，保障了教务数据的安全性。
