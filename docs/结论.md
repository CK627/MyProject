# 结论

本次毕业设计的主题是开发一套“智慧校园服务平台”。在这个过程中，我完整走过了一遍从前期调研、画原型图，到数据库设计、前后端编码，再到最后进行功能测试的软件工程全流程。

平台的核心架构选用了目前业界比较流行的前后端分离模式，前端采用了 Next.js 结合 React 和 TypeScript，后端则用 Python 的 FastAPI 框架写了接口。整体功能主要分为六大块：校园动态墙、悬赏互助任务、点对点即时通讯、虚拟钱包交易、信誉积分评价以及基于投票的社区审核。为了让平台跑得顺畅且安全，我在开发时也加入了一些关键技术，比如用 WebSocket 实现了消息的实时推送，用 JWT Token 做了接口的安全校验。经过多轮的联调测试，目前这个平台在电脑和手机浏览器里都能比较稳定地运行，基本达到了当初设想的设计目标。

跟大家平时常用的微信群、QQ群比起来，我觉得这个平台有几个明显的优点：
第一是针对性强。在微信群里找人代拿快递，钱给早了怕被骗，给晚了别人又不敢接。这个平台自带了“悬赏冻结”功能，任务发出去钱先冻结在系统里，做完了再自动打给对方，这在很大程度上保障了资金安全。
第二是有一套信誉门槛。系统会计算每个人的“优先分”（把信誉分和好评率结合起来），分高的人能优先接到任务，这样就能自然淘汰掉那些不靠谱的用户。
第三是管理起来没那么累。普通的贴吧需要管理员天天盯着删垃圾广告，而在这个平台里，不仅引入了普通用户的“踩”功能，高信誉的同学还能自动变成审核员一起投票删帖，形成了一个自治的社区环境。
相比闲鱼这种大平台，我们做的东西完全聚焦在校园内部，省去了快递邮寄的麻烦，熟人社会也更让人放心。当然，跟那些砸了重金做出来的成熟商业软件比，我做的这个系统在功能的丰富度和细节体验上肯定还是有不少差距的。

在整个开发和测试过程中，我也发现了几个明显的不足之处：
首先，虽然我用了响应式布局，但在部分小屏幕手机上，某些按钮和弹窗的交互体验还是有些别扭。
其次，钱包系统现在只能在系统里模拟充值，因为个人开发者很难申请到微信或支付宝的真实支付接口，这就导致它离真正上线运营还有一步之遥。
另外，因为即时通讯是基于 WebSocket 做的，只要用户把浏览器关了，有新消息就收不到推送提醒，这也是个比较遗憾的地方。
最后，后台缺少一个直观的数据大盘，看不到大家喜欢在什么时间段发帖或者发任务，不太方便以后做运营分析。

如果以后有机会继续完善这个项目，我觉得可以从下面几个方向着手：
首先，最直接的就是开发一个微信小程序版本。现在大家很少会专门去用手机浏览器打开一个网页，有了小程序，用户的接受度肯定会高很多。
其次，希望能想办法接入真实的支付 SDK，或者引入一些担保交易的机制，把资金流彻底打通。
第三，可以考虑加一点智能推荐的算法，比如某个同学经常接代取快递的任务，系统就优先把这类的任务推给他。
第四，业务模块还可以继续扩充，比如加一个专门的二手跳蚤市场版块，或者学霸辅导版块。
最后，在部署方面，目前还是手动上传代码运行的，以后可以学习用 Docker 把环境打包，配合自动化部署工具，这样升级维护起来会轻松得多。
通过不断打磨这些细节，我相信这个平台完全有潜力从一个简单的互助小工具，成长为一个能服务全校师生的综合型智慧校园平台。
