# 第六章 总结与展望

本文针对高校毕业设计管理中存在的文件提交分散、版本管理混乱及审核效率低下的问题，设计并实现了一套基于 B/S 架构的高校毕业设计文件综合管理系统。系统采用原生 PHP 8.4 与 MySQL 8.0 作为核心技术栈，结合 HTML5 分片上传、断点续传及 Glassmorphism UI 设计，构建了一个轻量级、高性能且易于部署的解决方案。研究成果主要体现在四个方面：首先，构建了高可靠的大文件传输机制，通过 Blob 切片算法有效解决了传统 Web 上传受限于服务器配置的痛点，实测支持 GB 级文件的稳定传输；其次，实现了业务逻辑与数据存储的深度融合，针对毕业设计场景设计的“宽表”结构实现了文档的自动规范命名与旧版本覆盖更新，确保了归档数据的一致性；再次，打造了闭环的教学管理工作流，开发了集可视化统计、快捷审批及一键打包下载于一体的教师后台，实现了全流程数字化管理；最后，建立了多层级的安全防护体系，通过 Session 强认证、SQL 预处理及全链路审计日志，有效保障了系统安全。

与现有的文件管理方案相比，本系统展现出了显著的优势。相较于传统的邮件或 FTP 方式，本系统实现了身份认证与学籍信息的自动关联，杜绝了匿名提交与命名混乱问题，提供了实时的状态反馈与进度可视化，交互效率显著提升；相较于通用网盘（如百度网盘、腾讯文档），本系统深度集成了教学业务逻辑，支持按班级、文档类型的精细化权限控制与批量操作，且数据私有化部署避免了公有云服务的数据隐私泄露风险，符合高校数据安全合规要求；相较于现有基于老旧技术栈开发的教务系统模块，本系统采用轻量级原生架构，部署维护成本更低，并引入了现代化的拖拽上传与毛玻璃 UI，交互流畅度与视觉体验更佳。

尽管系统已达成预期设计目标，但在实际应用与功能深度上仍存在一定的局限性。目前系统仅通过轻量级 JS 库支持 PDF 及简单 Office 文档的预览，对于复杂格式（如带有宏的 Excel、复杂排版的 Word）的渲染保真度不足，且不支持在线批注，难以满足深度的论文审阅需求。同时，虽然界面实现了响应式布局适配移动端，但在复杂的文件管理操作（如批量多选、拖拽排序）上，Web 端的触控体验仍不如原生 APP 流畅，存在一定的误触风险。此外，系统目前依赖用户主动登录查看状态，缺乏与微信、钉钉等主流 IM 工具的集成，无法实现审核结果的实时推送与强提醒，可能导致学生错过修改窗口期。

针对上述问题及未来教育信息化的发展趋势，后续研究建议从以下几个方面展开：一是深化在线协作与编辑能力，引入 OnlyOffice 或 Collabora Online 等成熟的文档服务中间件，将“文件流转”升级为“在线协同”，实现师生在系统内直接对论文进行批注与修改，彻底打通“提交-审阅-修改”的闭环；二是引入智能化数据分析，利用大数据与自然语言处理技术对文档进行格式规范性检测或内容查重预检，减轻教师初审压力，并基于提交时间数据分析学生的学习行为模式；三是探索云原生架构演进，随着用户规模的扩大，逐步将单体架构向微服务架构演进，将文件存储剥离至对象存储，并将核心业务容器化部署，以提升系统的弹性伸缩能力与容灾水平。
